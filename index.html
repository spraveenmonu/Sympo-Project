Common Vulnerabilities

These are real-world security weaknesses found in websites and systems every day.

🚪

Open Ports

Leaving unnecessary ports open on a server is like leaving doors unlocked. Attackers scan for open ports to find ways in. Always close ports you don't need.

Common risky ports: 21 (FTP), 23 (Telnet), 3389 (RDP)
📡

Insecure Protocols

Using HTTP instead of HTTPS, or Telnet instead of SSH, means your data travels without encryption. Anyone on the same network can read it.

Always use: HTTPS, SSH, SFTP, TLS
🔓

Weak Passwords

Passwords like "123456", "password", or "admin" can be cracked in seconds. Use long, unique passwords with numbers and symbols.

Bad: admin123 | Good: Tr@f!c_L1ght$_42
🐛

Unpatched Software

Old software has known bugs that attackers exploit. Regular updates and patches fix these vulnerabilities before attackers can use them.

Always update: OS, browsers, plugins, apps
🎣

Phishing

Fake emails or websites that look real but steal your information. Always check the URL and sender's email address before clicking links.

Fake: g00gle.com | Real: google.com
💾

Data Exposure

Websites accidentally exposing sensitive info through HTML comments, error messages, or publicly accessible files like robots.txt.

Check: View Source, /robots.txt, Console logs

+350 PTS PENDING

A proprietary security dongle validates activation keys using this disassembled x86 instruction routine: 

0x00401000: MOV  EAX, [INPUT_KEY]     ; Load decimal user input
0x00401005: XOR  EAX, 0x1337          ; Bitwise XOR with 0x1337
0x0040100A: ADD  EAX, 0x05A0          ; Add decimal 1440 (0x05A0)
0x0040100F: CMP  EAX, 0x2DEB          ; Compare with target 0x2DEB (11755)
0x00401014: JE   VALID_KEY_GRANTED    ; If equal -> Unlock flag!

🎯 Manual Mission Guide: 1. The assembly logic validates: (Input XOR 0x1337) + 0x05A0 == 0x2DEB (11755).
2. Invert the operations mathematically in reverse order: subtract 0x05A0 (1440) from 0x2DEB (11755), then bitwise XOR with 0x1337 (4919).
3. Convert your calculated value to decimal, enter it below, and click ▶ Step Instruction.
DEBUGGER // x86 REGISTER CPU EMULATOR
// CPU State: EAX=0x00000000 | ZF=0 | Stopped at 0x00401000. Invert the assembly operations and enter the key.
Tactical Guidance:
  1. Work backwards from target 0x2DEB (decimal 11755) to set Zero Flag (ZF) = 1:
  2. Undo ADD EAX, 0x05A0: Subtract 0x05A0 (decimal 1440) from 0x2DEB (decimal 11755).
  3. Undo XOR EAX, 0x1337: Recall that XOR is self-inverting ((A ^ B) ^ B = A). Apply XOR with 0x1337 (decimal 4919) to your intermediate value.
  4. Convert the resulting hexadecimal value to standard decimal format.
